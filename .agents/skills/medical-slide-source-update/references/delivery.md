# 资料包交付与后续增量更新

用户要求资料包时，推荐组织为：最新PPT、逐页讲稿、正式原文、补充原文、原图、当前文献清单、文件清单及哈希。只包含当前可用交付，工作脚本、验证页和失败下载页面留在私有工作目录。

当前清单说明：
- 基线PPT和实际页数、物理页/页脚编号关系。
- 此版本替换的页面、图号、文献版本。
- 正式全文、接受稿、HTML/XML全文、摘要和会议报告的不同状态。
- 仍缺全文、仅缺PDF格式、仍缺最终发表版本、题录待识别分别列出。
- 原文中的未解决冲突以及使用限制。

增量更新时同时更新PPT备注、独立讲稿、文献状态、补充资料清单、总资料包。把旧版本说明明确标为历史记录，或不纳入当前交付。不要只复制新PDF而遗漏当前清单；也不要声明旧ZIP已更新，实际只更新了目录。

## 保留模板的局部编辑

可以由演示工具完成作者编辑，再在确需避免全文件重导入变化时定向合并生成的页/备注及其依赖。合并后验证：
- 从presentation.xml关系解析实际页序，不假设slideN就是第N页。
- 每页通过自己的notes关系定位备注，不假设notesSlide编号相同。
- 内容类型使用正确的默认命名空间，新增图片/备注/图表所需条目完整。
- 引用图表用关系目标或已验证标题匹配；枚举顺序可能和左右位置不同。
- 页面位置调整后重新导出并目视检查“图表、统计解释、标题”三者对应。
- 缓存与工作簿同步。系列名若被误写成单位字符串公式，应先核实工作簿标题单元格，再修复为有效内部引用。

这些修复只在实际发生问题时使用，不要求每次重写OOXML。

## 打包辅助脚本

`package_release.py`使用Python标准库，不联网、不修改原始文献；在ZIP内添加`release-manifest.json`，记录输入文件的大小及SHA256。拒绝覆盖已有ZIP、拒绝符号链接和把ZIP写到源目录内部，以避免递归与混入外部文件。打包后读取每个成员验证哈希。

示例：
```sh
python3 scripts/package_release.py /absolute/path/release-folder /absolute/path/new-release.zip
```

脚本成功只证明文件包完整，不证明医学事实、原图质量、演示效果或PPT可编辑性。
